## What this is

Phase 3 slice 3A of the plugin venture's arc (#251): remote turns can ride the
**runs plane** — `POST /v1/runs` → `GET /v1/runs/{id}/events` (SSE) →

## What it buys, today

- **A real Stop.** Today's Stop stops the app listening; the host keeps generating
  and spending. On this plane it is a genuine server-side interrupt.
- **Durable answer recovery.** A dropped stream no longer risks the answer: the run's
  own status is authoritative for an hour, so recovery is a poll, not a replay.
- **The road to in-chat approvals and steering** (3B/3C), which are structurally
  impossible on the sessions plane.

## The blocking probe ran before any code

Both open questions were answered on the wire against the live Mac gateway, and both
changed the design:

- **Runs WRITE the session row but never READ it.** Server-side history, `openSession`
  and fork all survive — but the app must supply per-turn context, and a missing
  history does **not** error: the agent answers plausibly from long-term memory.
  That is why the history bar asserts a marker word rather than "an answer arrived."
- **The app's existing attachment shape is rejected** by `/v1/runs` (`400 No user
  message found in input`); the message-array wrap works end to end.

## Honest disclosures — read this part

- **Not "sessions plane byte-untouched."** Its *behavior* is pinned unchanged (and a
  test asserts the switch-off path never touches `/v1/runs`, and vice versa), but
  `SessionsHermesClient.swift` gained seams: ~10 visibility widenings tagged
  `// runs-path-visible (#283)`, `decodeRunUsage` became static, plus two extracted
  helpers and the dispatch branch.
- **Artifacts lose their content on this plane.** The runs stream carries no tool
  arguments, so an agent-written file renders as a chip with a path and no inline
  content. That is honest absence, pinned by a test; fabricating content would be a bar
  failure. Slice 3D restores it via a plugin hook.
- **`.modelResolved` never fires here** — the runs completion carries no runtime block,
  so the UI shows honest absence rather than a guessed serving model.
- **Recovery has silent windows.** Worst case ≈ 60s stall detection + up to 120s poll ≈
  3 minutes of live-looking screen; the sync path is capped at 20s (restoring #145
  Part A's "everything non-stream gets 20s" policy, which the first sync implementation
  had falsified). The knobs are guesses — the device bar asks for the real number.
- **A walk-away no longer kills the host run — by ruling, and it is yours to overturn.**
  The whole-branch review caught that the stop had been wired onto the *teardown*
  primitive, so switching threads or starting a new chat mid-turn would have silently
  destroyed an answer the sessions plane preserves. Ruled for sessions-plane parity:
  only an explicit Stop (tap, Siri Cancel, intent cancel) reaches the network. If you'd
  rather walking away also stop the host burning tokens, it is a one-line flip; both
  directions are pinned.
- **Known limitations, recorded not fixed** (all behind the OFF switch): `activeRunContext`
  is a single slot, so an overlapping sync send and streamed turn contend for Stop; a Stop
  tapped before the submit returns has no run id yet and degrades to today's behavior; a
  self-stopped sync run surfaces as an error string; history rides every submit unbounded
  (parked deliberately as parity with what the sessions plane feeds the agent — revisit
  at 3E).
