01 — HOW YOU RUN IT

Pairing is optional.

Most self-hosted apps are useless until you've stood up a server. This one isn't. Install it and it already works — a host is the upgrade, not the entry fee.

SOLO ZERO HOST SETUP

Everything on the device.

A full local backend on Apple's FoundationModels framework, behind the same client seam as the hosted path. Context-window-aware condensation instead of errors. Nothing leaves the phone.

▸Streaming chat, sessions drawer and persistence
▸Read-aloud, and a sessions history that survives relaunch
▸Device tool belt: calendar, reminders, contacts, weather, health, alarms
▸Siri and App Intents; conversations index into Spotlight
▸Works in airplane mode — nothing leaves the phone
PAIRED + A MACHINE YOU OWN

Your whole agent, on tap.

Point it at a Hermes host over Tailscale. Chat, sessions, models, and mid-turn steering talk straight to the Sessions API; the talaria plugin on the same gateway carries pairing, query-time phone asks, and the inbox. Pair more than one machine if you like — each profile keeps its own key in the Keychain.

We'd rather you knew.

Developed and used daily on real hardware. Expect rough edges — here is exactly where they are, subsystem by subsystem, the same table that's in the README.

WORKING

WORKING

Tool calls & agent files
WORKING

Inbox / Directives
WORKING
Approvals, reminders and the daily briefing land in the in-app inbox; approve or dismiss in place and the verdict goes back to the host.
Model picking
WORKING
The full provider roster comes from the gateway's own API. A pick applies as a per-turn model lock and takes effect immediately.
Widgets & Live Activities
WORKING
Status, health and briefing widgets; alarm Live Activity; lock-screen controls.
Share extension
WORKING
Share URLs, images, files and text into Hermes from any app.
Phone queries
WORKING
Your agent asks the phone for location, health, calendar, weather and motion at query time. Deliberate opt-in with per-sensor grants; nothing streams in the background.
Voice mode
WORKING · CAVEAT
Realtime speech-to-speech plus an on-device fallback engine. Echo and self-interruption tuning is actively in progress.
Notifications
REMOVED BY DESIGN
The app posts no notifications and registers for no push. Chat, the inbox and Live Activities carry state in-app.
CarPlay
PARKED
Scene and voice manager are built but disabled, pending Apple's discretionary capability grant.

03 — CAPABILITIES

What it can actually do.

Every action the agent takes on your device is confirmed in-app before it fires. Nothing runs behind your back.

01
On-device brain
A complete local chat backend on FoundationModels, behind the same client seam as the hosted path. Sees the photos you attach — on-device, the picture never leaves the phone. Context-window-aware condensation instead of errors.
02
Streaming chat
Server-sent events from the Hermes Sessions API. Markdown, code blocks, inline images and mirrored agent artifacts, rendered natively.
03
Voice mode
Realtime WebRTC speech-to-speech with server-side voice, continuous mic and barge-in — bootstrapped through the talaria plugin, with an on-device engine when you're unpaired or offline.
04
Device tool belt
Calendar, reminders, contacts, WeatherKit, health and media — plus real alarms and timers through AlarmKit. Every action confirmed before it fires.
05
Phone-aware answers
Your agent asks the phone for location, health, calendar, weather and motion at query time. Per-sensor opt-in; nothing streams in the background.
06
Inbox & directives
To-dos, approvals, reminders and a daily briefing pushed from the host. Approve or dismiss in place — the verdict lands back on your machine.
07
Widgets & Live Activities
Agent status, health tiles and briefing widgets. Alarm Live Activities and lock-screen toggle controls.
08
Share extension
Send a URL, up to four images, a file or plain text straight into Hermes from the iOS share sheet.
09
Multi-host profiles
Pair a desktop and a dev box. Each profile keeps its own API key in the Keychain, and switching is one tap.

04 — ARCHITECTURE

Two paths. Nothing in the middle.

Chat connects directly to the Sessions API — model selection and mid-turn steering ride the same connection — and the talaria plugin on the same gateway carries pairing, phone asks, and the inbox. The relay tier is retired — current builds don't call it.

──→ PLUGIN LINK

──→ RETIRED
The relay tier's jobs are all gone: the voice bootstrap moved to the plugin (2026-08), pairing, phone asks, the inbox and artifact delivery ride it too, and sensor ingestion is gone outright (query-time asks instead). The sidecar stays in the repo for history — current builds never call it.
HermesMobile Relay :8000
python sidecar · uvicorn → connector → hermes_mobile MCP
RETIRED models shim · :8765 — current builds never call it. Model picking is native to the gateway now.
NETWORK
Tailscale is the recommended path — hostnames and IPs reach both services without exposing anything to the public internet.
AUTH
Bearer token on the gateway; each paired profile stores its own key in the iOS Keychain, never in a config file.
FAILURE MODE
Everything restarts independently. If the host is down entirely, the on-device brain takes over — chat, voice, and vision all run without it.
